Docker & Portainer

  • Image: ghcr.io/jbkunama1/hai.musike:latest
  • Architekturen: Linux amd64 und arm64
  • Externes Netzwerk: highfishNetwork
  • Weboberfläche: http://SERVER-IP:4180
  • Reverse-Proxy-Ziel: http://hai-musike:4180
  • Persistenz: Bibliothek unter /data, Cache unter /cache

Diese Seite ist die Projektdokumentation, nicht die Player-Oberfläche. Öffne den Player auf deinem eigenen Server.

Schnellstart

Ersten erfolgreichen Build und GHCR-Zugriffsrechte prüfen. Netzwerk muss bereits existieren.

git clone https://github.com/jbkunama1/hAI.Musike.git
cd hAI.Musike
docker network inspect highfishNetwork
docker compose up -d

In Portainer alternativ die Compose-Datei aus dem Repository als Stack deployen.

Täglicher Upstream-Build

GitHub Actions baut täglich um 03:30 UTC aus dem aktuellen Musike-Quellcode. Zeitpläne können verzögert oder bei längerer Repository-Inaktivität deaktiviert werden. Buildstatus unter Actions prüfen.

Der laufende Container wird dadurch nicht automatisch aktualisiert. Vor Updates Bibliothek exportieren; anschließend:

docker compose pull
docker compose up -d

Für einen festen Stand einen Build-Tag oder Image-Digest einsetzen. Aktuelles Upstream kann ungetestete Änderungen enthalten.

Betrieb & Sicherheit

Zugriff über einen abgesicherten HTTPS-Reverse-Proxy oder ein privates VPN bereitstellen. YouTube kann Rechenzentrums-IP-Adressen blockieren. Die Region ist DE; eine deutsche Oberfläche wird dadurch nicht hinzugefügt.

Vorhandene Volumes nicht löschen. Vollständige Konfiguration, Backup und Fehlerdiagnose stehen in der README.
